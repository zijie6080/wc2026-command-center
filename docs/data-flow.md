### 2.3 数据流 ③ —— 赛后数据结算 (Post-Match Settlement)

**触发时机:** 比赛结束 (status: finished) · 一次性完整结算

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                     FLOW ③ — 赛后数据完整结算                                      │
│                                                                                   │
│  ┌──────────────────┐                                                             │
│  │  Match Finished  │  ← 比赛状态变为 finished                                    │
│  │  (status change) │                                                             │
│  └────────┬─────────┘                                                             │
│           │                                                                        │
│           │ 触发 Webhook 或 Cron 检测                                              │
│           ▼                                                                        │
│  ┌──────────────────────────────────────────────────────────┐                     │
│  │              赛后结算流程 (Post-Match Pipeline)             │                     │
│  │                                                           │                     │
│  │  Phase 1: 数据校验 (5 分钟内)                              │                     │
│  │  ┌────────────────────────────────────────────────────┐   │                     │
│  │  │ · Football API 拉取完整赛后数据                      │   │                     │
│  │  │ · 对比赛中数据，修正误差                             │   │                     │
│  │  │ · 回填 MatchStats 完整 65 字段                       │   │                     │
│  │  │ · 回填 PlayerStats 完整 63 字段 (所有上场球员)       │   │                     │
│  │  │ · 计算 pass_accuracy, shot_conversion_rate 等派生字段│   │                     │
│  │  └────────────────────────────────────────────────────┘   │                     │
│  │                         │                                  │                     │
│  │  Phase 2: 评分计算 (赛后 15 分钟内)                        │                     │
│  │  ┌────────────────────────────────────────────────────┐   │                     │
│  │  │ · AI 评分模型消费 PlayerStats 数据                   │   │                     │
│  │  │ · 计算每位上场球员的 ai_rating (1.0-10.0)           │   │                     │
│  │  │ · 确定 is_mvp = true 的球员 (评分最高者)            │   │                     │
│  │  │ · 写入 PlayerStats.ai_rating                        │   │                     │
│  │  └────────────────────────────────────────────────────┘   │                     │
│  │                         │                                  │                     │
│  │  Phase 3: 聚合更新 (评分完成后)                            │                     │
│  │  ┌────────────────────────────────────────────────────┐   │                     │
│  │  │ · 更新 Standings: wins/draws/losses/goals/points    │   │                     │
│  │  │ · 重新计算 TeamStats: SUM + AVG 全量聚合             │   │                     │
│  │  │ · 更新 Teams.status (如有淘汰)                      │   │                     │
│  │  │ · 更新 Players.yellow_cards_accumulated             │   │                     │
│  │  │ · 生成赛后战报 (AI Article)                         │   │                     │
│  │  └────────────────────────────────────────────────────┘   │                     │
│  │                         │                                  │                     │
│  │  Phase 4: 预测结算 (下一轮)                               │                     │
│  │  ┌────────────────────────────────────────────────────┐   │                     │
│  │  │ · 结算用户预测: is_settled + is_correct + points    │   │                     │
│  │  │ · 更新 User.prediction_accuracy                     │   │                     │
│  │  │ · 触发 AI 预测模型重新运行 (更新晋级概率)            │   │                     │
│  │  └────────────────────────────────────────────────────┘   │                     │
│  └──────────────────────────────────────────────────────────┘                     │
│                                                                                   │
│  时间线: 5min(数据) → 15min(评分) → 30min(聚合+通知) → 1h(预测更新)               │
└─────────────────────────────────────────────────────────────────────────────────┘
```

### 2.5 数据流 ⑤ —— Supabase Realtime 推送 (WebSocket)

**触发时机:** 数据库写入事件 → 自动推送到订阅客户端

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                     FLOW ⑤ — Realtime 推送链路 (WebSocket)                         │
│                                                                                   │
│  ┌──────────────────────────────────────────────────────────┐                     │
│  │               Data Change Occurs                         │                     │
│  │                                                           │                     │
│  │  Matches.score_ft_home 由 1 变为 2                        │                     │
│  │  MatchEvents 插入一条新记录 (type='goal')                  │                     │
│  └────────────────────────────┬──────────────────────────────┘                     │
│                               │                                                    │
│                               │ PostgreSQL WAL (Write-Ahead Log)                   │
```
